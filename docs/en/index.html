Your Garmin and Strava data, together, at home.

Garmin knows how you slept. Strava knows what you rode. Neither puts the two side by side, because they don't talk to each other. Cairn does — on your own server, in a database you control.

The problem

You string together a heavy week. Your HRV has been dropping for three nights and your resting heart rate is creeping up — Garmin knows that. You've stacked up enduro descents and a three-hour road ride — Strava knows that. Nobody puts the two together, and that is exactly where a building overload shows up.

Cairn syncs both sources into one database, recognises that a ride appearing on both sides is a single ride, and lines a night's recovery up against the same day's training.

What it does

Nightly sync

One pass per night into your database. Raw JSON and the original .fit files are archived: nothing is lost, everything can be replayed.

Deduplication

A ride recorded on your watch lands in both Garmin and Strava. Cairn keeps one, taking the sensors from one and the gear from the other.

Recovery × load

Sleep, HRV and resting heart rate aligned to the same date as your activities. The join neither Garmin nor Strava can make.

Weekly summary

The app ships with its own model: your week is put into words offline, with nothing to install. It computes nothing — every figure comes from the database, and any it invents is rejected.

Desktop application

One window to link your accounts, trigger a sync and read the essentials. Portable: kept next to its settings file, it runs from a USB stick.

Second-by-second streams

.fit files are decoded into 1 Hz series in TimescaleDB: exact heart rate zones, cardiac drift, fine-grained ride analysis.

Install the server

The server is a docker-compose stack: PostgreSQL with TimescaleDB, the sync service, and Grafana. Built to run in an LXC container or a small VM. 

git clone https://github.com/devfrp/Cairn.git && cd Cairn
cp .env.example .env
# fill in the passwords and the encryption key
docker compose up -d

Then link your accounts. Since Garmin has no public API for individual use, Cairn opens a session and keeps the token encrypted at rest — your password is never stored. 

docker compose run --rm cairn auth garmin
docker compose run --rm cairn auth strava

Download the app

A standalone desktop application: nothing to install, no Python interpreter needed. It connects to your own database and is where you link your accounts, run syncs and read the essentials at a glance. The server itself stays deployed by docker-compose.

Each package carries its own language engine and the qwen3:0.6b model — hence its size, around 800 MB. That is the price of a summary that works offline, with nothing to install and no data leaving the machine. If you already run Ollama, put its address in the settings and Cairn will use that instead.

Every file ships with its SHA-256 checksum. The packages are neither signed nor notarised, so Windows and macOS will warn you on first launch.

On Linux and macOS, in one command:

curl -fsSL https://devfrp.github.io/Cairn/get.sh | sh

Your data stays yours

Cairn only talks to Garmin and Strava, and only to fetch your own data. No third-party service, no telemetry, no account to create. The database and activity files live on your machine, and the page you're reading loads no remote fonts and no external scripts.
